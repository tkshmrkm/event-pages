- `index_v1.html`、`index_v2.html`、各サンプルを直接上書きしない。
- 交通はスマートフォンでも必ず4列のままにする。
- 日付ナビ、タブ、フォントはHRS方式を維持する。
- フォントは `BIZ UDPGothic`, `Yu Gothic UI`, `Meiryo`, `system-ui`, `sans-serif`。
- 飛行機はカラー絵文字ではなく共通の `.flight-mark` を使う。

## 家族タブの構成（今後の共通ルール）

家族タブは旅程タブの再掲にしない。**「どの日にどこにいて何をしているか」を
視覚的に掴めること**を最優先にする。

- 先頭付近に `どこにいるか` の一覧を置く。1日1行で、**都市名を最大文字**にする。
  日付と人物名はその手がかりに徹し、小さくする。別行動の日は人物ごとに分け、
  合流後は1つにまとめて、合流したことが見た目で分かるようにする。
- 時差は、タイムゾーン略号やUTCオフセットではなく**時差の数字を最大文字**にする
  （`−7時間` を38px、`CEST・UTC+2` は補足の12px）。家族が使うのは差の方。
- 日別の詳細は家族視点に圧縮する。載せるのは、居場所が変わる出来事
  （フライト、到着、チェックイン）、日中なにをしているか、
  **連絡が取りにくい時間帯（機内）**だけ。駅から駅への移動は載せない。
- タグにイベント種別（TechEx / EuroBLECH / 工場見学）を持ち込まない。
  家族から見れば全部「仕事」なのでまとめる。
- フライト情報ブロックは現状の作りを維持する。

2026-08-14の実測: 日別詳細は52行→31行、家族タブ全体は393px幅で
10350px→9708pxになり、`どこにいるか`（1283px）を追加した。
`validate_v3.mjs` で行数の上限と、都市名・時差の文字サイズを検査している。

## 文章の調子（今後の共通ルール）

このページは現地で見るフィールドガイドであって、読み物ではない。

- **常時表示の補足行は30字程度までの事実に留める。** 理由、判断材料、条件は
  折り畳みの中へ入れる。地の文で理屈を説明しない。
- **常時表示行の末尾に句点を付けない。** ラベルであって文ではない。
  複数文になる場合だけ文間に句点を使い、末尾には付けない。折り畳みの中は対象外。
- 2026-08-14時点の実測: 旅程タブの常時表示テキストは26行→21行、平均37字→27字、

## 地図リンクの張り方（今後の共通ルール）

**地図リンクは場所名そのものに張る。** 「地図」「MAP」といった別リンクを横に出さない。

- 交通の出発・到着地、宿泊のホテル名を、いずれも `<a class="place">` で包む。
- `機内` や `帰宅` のように実在の場所を指さない語にはリンクを張らない。
- 見た目は交通の場所名と同じ（`#2A5FA0`・太さ600・下線なし）にそろえる。

## 乗り継ぎ・待ち時間の書き方（今後の共通ルール）

乗り継ぎと出発待ちの折り畳みは、**`やること` と `過ごし方` の2つだけ。**
特定の過ごし方を既定にしない。

- 主表示は `🕐 <地点>で乗り継ぎ（<所要>）` だけにする。理由も手順も主表示に書かない。
- 所要の書き方は交通手段の欄と同じ規則にそろえる。**推定には `約` を付け、
  時刻表どおりの区間には付けない。** セントレアの出発待ちは起点が「空港到着目安」
  なので `約3時間`、香港の乗り継ぎは前後とも定期便なので `3時間45分`。
- **`やること` は、やらないと困ることだけ。** チェックイン、保安検査、出国審査、
  搭乗口の確認、セキュリティ再検査、**コンコース間の移動**、Visit Japan Webの準備。
  館内の移動は過ごし方ではなく、目的地へ着くための手順なのでここに入れる。
- **`過ごし方` は、空き時間の使い道。** ラウンジ、無料シャワー、飲食、休憩場所を
  同じ階層に並べる。どれも並列で、ラウンジを既定にも推奨にもしない。
- **ラウンジ専用の見出しを作らない。** `ラウンジで過ごす` `ラウンジを使わずに過ごす`
  という2本立てはやめた。ラウンジは `過ごし方` の中の1行で、4系統がその下にぶら下がる
  （`.opt-sub`）。
- 4系統はこの順で必ず全部並べる。どれかを既定にも推奨にもしない。
  1. `エアライン`（搭乗クラス・航空会社ステータス・招待条件）
  2. `Priority Pass`（会員資格）
  3. `一般有料`（会員資格なしで買える）
  4. `カード付帯`（クレジットカードの特典）
- 旅程に書くのは4系統の名前と営業時間まで。**利用資格は準備タブが持つ。**
  確認できていない系統は、系統ごと消さずに「未確認」と書いて残す。
- 生成は `build_v3.mjs` の `todoFold()` / `spendFold()` / `loungeOption()` の3つだけを使う。
  同じ形のHTMLを別の場所に手書きしない。

10/17（村上・セントレア約3時間、香港3時間45分）、10/18（美馬・金築・セントレア約3時間、

## 交通行と操作のルール（今後の共通ルール）

### 交通手段はすべてアイコン

フライトだけ絵で他が矢印、という不揃いにしない。中央列は必ずアイコンにする。

- フライトは共通の `.flight-mark`、それ以外は `.mode-icon`。寸法と色をそろえる。
- 鉄道 / 徒歩 / 車（タクシー・Uber）/ 手段未定 を `modeKind()` で振り分ける。
- **決まっていない手段を、決まっているように描かない。** 手段そのものが未定のときだけ
  `unknown`（?）にして色も要検討のオレンジにする。便だけ未定（「列車候補を確認」）は鉄道でよい。

### 帯の色と線種は確定度を表す

凡例に載せた意味のとおりに使い分ける。日ヘッダーの色は予定の**種類**であって確定度ではない。

- `route-review`（オレンジ）= 手段や便が未定
- `route-estimate`（点線）= 手段は決まっていて時刻だけが目安
- 手段が決まったらオレンジから点線へ移す。10/22のタクシー（Uber）確定がその例。

### 日跨ぎ便で着いた日は「◯◯着」を出す

到着便の4列交通は前日側にあるため、到着日の人物レーンだけを見ると着いたことが
分からなくなる。日跨ぎ到着3件（10/18 AMS、10/19 FRA、10/25 HKG）は
その日の先頭に `◯◯着` を出す。同日中の到着は直前の4列交通が示すので付けない。

### Tailwind風マークアップ — 効いていないものは削除（2026-08-15に決定）

**使わない。** 生成物に残すのは、CSS側に受けがあるクラスだけにする。

ビルドが `v3.css` 2枚（HRS＋EB）を走査して、どのルールも受けていない
Tailwind風のクラスを落とす。**346トークンを削除した。**
`index.html` は 151,476 bytes、Tailwind風は933件61種が残る（すべて受けがある）。

計算後スタイルは削除前と**完全に一致**する。393要素の背景色・文字色・罫線・角丸・
余白・文字サイズ・グリッド指定のハッシュも、文書高さ3,635pxも同じ。見た目は変わらない。

**CSSOMをブラウザ内で読んではいけない。** ビルドは一時ディレクトリでページを開くため、
相対パスのlinkが解決されず `document.styleSheets` が空になる。「どのルールも
受けていない」が常に真になり、効いている40種まで巻き添えで消える。実際に一度踏んだ。
CSSはNode側で読んで `cssKnownClasses` / `cssKnownSubstrings` として渡す。

`v3.js` はTailwind風クラスを一切使っていないので、JS側の巻き添えは無い
（使うのは on / off / today / chip / tab / day / t / d）。

あとからCSSを足せば次のビルドで自動的に残るので、消し過ぎが固定化しない。
検証に「生成物のクラスはすべてCSSが受けている」を追加した。
