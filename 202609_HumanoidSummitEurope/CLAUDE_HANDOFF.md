### 主要タブは5つ（概要 / 旅程 / 視察 / 準備 / 記録）

**この点は2026-08-15に両イベントでそろった**）。

**準備タブには寿命がある。** 出発前に要対応タスクが埋まったら、タブごと畳んでよい。
畳めるようにするため、中身は要対応タスク1枚だけにしてある。利用フライト・宿泊・

`validate_v3.mjs` が、要対応タスクが準備にあること・3枚が準備に無く旅程にあることを
見ている。**準備に現地用のものを戻さないこと。**

畳んだあとは `概要 / 旅程 / 視察 / 記録` の4つになる。

タブの左右パディングは6px。5タブだと8pxでは393pxに12px足りず、記録の右端が
黙って切れる（スクロールバーはCSSで消してある）。6pxで5×68=340pxに収まる。

残りはすべてセッション表と講演ごとの記入欄だった。名前のせいでフライト・宿泊・地図を

場所ではなく行為。視察なら展示会・講演会・工場見学・企業訪問を全部覆うので、
SIGGRAPH AsiaやLOGIMATでもそのまま使える。

**内部キーは変えていない**（`data-tab="venue"` / `id="tab-venue"` / ストレージの
`ses:` プレフィックス）。表示名だけを替えた。保存済みのタブ状態と記録が壊れるため。
EBはまだ「会場」のまま。そろえるかは未決。

タブ名は2文字まで。実測で「イベント」は13px、「セッション」は26pxはみ出す。

### 概要タブは索引であって内容ではない

出張概要 / 日程概要 / イベント概要 / 施設概要 の4ブロック。各ブロックは
**1行の事実と詳細タブへの導線**に留める。ここに周辺レストラン・観光地・ラウンジを
集めると全タブ中で最も長いタブになり、「ひと目で俯瞰する場所」でなくなる。
それらは日付に紐づくものが旅程、参照用が旅程末尾のリンク集にある。

**日程概要は `FAMILY_DAYS` から生成する。手で書かない。** 日程を1回直した時点で
概要だけ古くなり、全体を見る場所なのでズレの実害が最も大きい。1日1行の
「主な内容」は `OVERVIEW_MAIN_KIND_ORDER` の優先順で代表イベントを選ぶ。
`flight` は `move` より上。moveを上にすると9/14が「入国審査…各自帰宅」を拾い、
その日の主役である19:35のセントレア着が消える。

**状態の札は概要に置かない。** `CLAUDE.md` の「状態を持つ単位は予定1件」に従い、
札の所有者は旅程と視察。複製すると片方だけ古くなる。未確定の日は、元テキストの
「。」以降を `.ov-note` で小さく添えるだけにする（9/11の「訪問先は未発表」）。
どの日を未確定とするかは冒頭の警告バナー（`UNDECIDED_BANNER`）が正本で、
バナーに無い日付へ札を付けようとするとビルドが止まる。

主催・規模・前回開催だけは**リポジトリ外の事実**。2026-08-16に
humanoidrobotssummit.com と acgrobot.com を開いて確認した。参加1,000名超・
500社超は主催者の見込み値、前回500名超は主催者が実績として書いているもの。
**見込みを実績として書かない。** 画面には「（主催者発表）」を常時表示し、
検証の有無と出典は折り畳み「数字の出どころ」に入れてある。登壇者数は公式サイトの
同一ページに「30+」と「40」があり判断できないので載せていない。
これらは元HTMLに無いのでソース照合の対象外。それ以外の固有名詞と数字は
すべて `overviewFacts` で元HTMLとの一致を確認してから書く。

### 利用フライトはカード（表ではない）

1区間を「出発 → 便名 → 到着」の三つ組にし、間に乗り継ぎ、見出しの右に総所要。
様式は `shared/trip-field/core.css` の `.flight-card`。EBの家族向けで一度作り、
家族には過剰として外したもので、EBのv3.cssにマークアップ無しの規則だけが
残っていたのを共通基盤へ引き取った。

値は `FLIGHT_JOURNEYS`。`buildFlightCards` が組み立て前に元HTMLとの一致を確認し、
区間数と乗継数が合わなければ止まる。**中央列は96pxしかないので機材と所要だけ**を
置く。機内食のような長い注記は `.flight-note` として区間の下に全幅で出す
（中央列に入れると3行に潰れて到着側へ迫る）。

### 旅程は表ではなく divスタック

`<table class="tl">` をやめ、`.tl-stack` の中に `.action`（2列）と
`.route-four`（4列）を並べる。**両者の第1列を同じ幅にすることで、
2列の行と4列の行で時刻が縦にそろう。** `<table>` の `colspan` ではこの整列が作れない。

時刻列は112px。表のときは列が内容に合わせて自動で広がったが、gridは広がらない。
`13:00〜14:00` が112px要るので、そこに合わせたうえで折り返しも許している。

### 4列化はフライト4区間のみ

フライトは `X発 → Y（便名・機材・所要）` という一定の形なので分解できた。
鉄道37件と徒歩の行は出発地・到着地・所要が1つの文に入っており、
分解は内容の書き換えになる。**やるかどうか自体が未決。**

到着行（`HEL 着` など）は乗継や入国手続きを持つ別の出来事なのでまとめない。

### 家族印刷版は5セクション

`出張サマリー / 時差・気候 / 日程詳細（家族向け） / 宿泊先情報 / 緊急連絡先`。

家族が最初に知りたいのは「どの日にどこにいて、いつ連絡が取れないか」。
以前は時差の説明と8行の表が同じ重さで並び、それが読み取れなかった。

### 時刻は現地時刻が既定、日本時間は明記して併記する

EUROBLECHは「時刻はすべてその場所の現地時刻」と宣言して換算しない。
**HRSは日本時間への換算も残す。** 家族が自分の時計で読めるようにするため。
`.timezone-lead` で読み方を宣言する。機内（連絡が取れない時間帯）は日本時間で出す。

### 時差カードのゾーン名に国旗絵文字を使わない

EUROBLECHは `🇯🇵 日本` としているが、Windowsでは国旗に合成されず `JP` `DE` と
文字で表示される。実機で確認済み。`日本` `ドイツ` の文字だけにする。

### 既定表示が「文字」の絵文字を使わない

`🗓` U+1F5D3、`🖨` U+1F5A8、`🗺` U+1F5FA は既定が文字表示なので、
異体字セレクタ無しだと黒い輪郭グリフになる。EUROBLECHが持つ
`line-icon` のモノクロSVGへ置き換える。交通アイコンをSVGに統一したのと同じ理屈。

### 「＋詳細」トグルは廃止

補足を既定で隠すのは現地で見落としの元になる。EUROBLECHにも無い。
ボタンだけ消すと `.note` と `.dt` が永久に隠れるので、CSSで常時表示にした。

保存値は読み込み時に `store.del('detail')` で落とす。書き出しが除くのは
`ui:` 付きのキーだけなので、残すとバックアップJSONに毎回入り、
読み込んだ端末へも複製される。古いJSONから復活しうるので、この処理は常設。

### 長い補足は折り畳みへ

常時表示は30字程度の事実まで。理由・判断材料・条件は `details.fold` の中へ。
`summary` は中身を示す語にする（`やること` `過ごし方` `ラウンジの利用資格`）。
`続きを読む` は使わない。

**字数は目安であって基準ではない。** 30字を超えても単一の事実なら常時表示に残し、
短くても理由の説明なら畳む。分けるのは長さではなく、事実か理屈か。

規則の本体は `../CLAUDE.md`、`../OVERSEAS_TRIP_LAYOUT_SUMMARY.md` の4.5節、
`../shared/trip-field/README.md` にある。

`build_v3.mjs` の `FOLD_NOTES` が対象一覧。`lead`（先頭の一致文字列）で
`.note` を特定し、まるごと折り畳みへ移す。`visible` を持つ項目だけ
「常時表示の事実 ＋ 折り畳みの理屈」へ分ける。`visible` が元の文の先頭と
一致しなければビルドが止まるので、分割のつもりで書き換えることはできない。

**2026-08-14の8件は `<span class="note">` しか見ておらず、
`<div class="note">`（プラン内の補足）が丸ごと残っていた。** 2026-08-15に
12件を追加して計20件。旅程タブで常時表示30字超なのは、意図して残した事実4件だけ
（対戦カード76字、ICEの所要40字、Porscheplatzへの経路36字、費用に含む区間54字）。
`.note` は `span` と `div` の両方があるので、片方だけ数えない。

## アイコンは全部モノクロSVG（2026-08-15）

生成物に絵文字を1文字も置かない。`LINE_ICON_PATHS` が41種のSVG、`EMOJI_ICON_MAP` が
絵文字との対応表。**対応表に無い絵文字を見つけたらビルドが止まる**ので、絵文字を足すと
必ずここで気付く。国旗は `dropFlags` で落とす。`flash()` はtextContentなので
SVGを置けず、`stripScriptEmoji` が絵文字だけ落とす。

処理は `buildDocument` の最後で走らせる。交通手段の変換（✈→`.flight-mark`）が終わり、
机上用印刷版がスクリプトを落としたあとでないと、対象が変わって数が合わなくなる。

**それまでは🖨🗓🗺の3文字だけを置き換えていた。** 検証もその3文字しか見ていなかったので、
同じくWindowsで黒い輪郭になる14種49箇所と、カラー絵文字35種が素通りしていた。
検証は `Extended_Pictographic` で数える形に変えた。

`.line-icon` は `inline-flex` の原子的インライン箱なので、アイコンと語の間の改行機会を
文字（WORD JOINER）で抑えられない。凡例など「アイコン＋語」を並べる行で、アイコンだけが
行末に残ることがある（2箇所）。絵文字のときも同じ位置で折り返していたので悪化ではない。

気温を押し出していた。** 原因は出典と統計期間を表の列として持たせたこと。

### 2. `.line-icon` が文字より大きい（オンライン版）→ em基準にした

`.line-icon` は幅・高さとも**固定19px**で、置かれている場所の文字は13〜16pxだった。

`.flight-mark` と `.mode-icon`（20px）は専用の列に入るので固定値でよいが、
`.line-icon` は見出しやボタンの文中に置くので文字サイズに追従させる。
`width/height:1.15em`、`margin-right:.3em`、`vertical-align:-.2em`。
13pxの `.btn` では14.9pxになる（実測、比1.15）。

`shared/trip-field/core.css` に置いた。HRS側（`build_v3.mjs` の `outdoorCss`）は
複製を持たず、共通定義をそのまま使う。規則は `CLAUDE.md` と
`shared/trip-field/README.md` にも書いた。

HRSの `v3.css` を先に読み、自分の `v3.css` を後に読むので、いまはそちらが勝つ。
